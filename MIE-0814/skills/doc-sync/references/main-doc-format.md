# 主文档格式模板（PROJECT-SYNC-<date>.md）

> 主文档 = 概览（不是正文）。用户看完知道"项目在干什么 + 有哪些待决策 + 每个 flow 长什么样"。

## 头部

```md
# <项目> 项目现状同步（<date>）— 多线 workflow 总览

> 目的：快速同步多条线颠覆后的设计全貌（workflow 级，非细节）。
> **👤 唯一 human 入口 = §8 待你决策清单**（详细在 [00-待决策清单.md](00-待决策清单.md)）——只需看那一节决定，其余读完即可。决策后主副文档自动同步。
```

## 方向 × 阶段总览（项目全景，必含）

```md
## 0.5 方向 × 阶段总览

> 每个方向/项目当前处于哪个阶段——**调研 → 计划 → 实现 → 已实现 / 已推迟**。一眼看全貌。

| 方向/项目 | 阶段 | 说明 | 详档 |
|-----------|------|------|------|
| <方向 1> | 🔵 调研 / 📋 计划 / 🟡 实现 / ✅ 已实现 / ⏸ 已推迟 | <一句话> | [NN-主题](NN-主题.md) |

**阶段图例**：🔵 调研 → 📋 计划 → 🟡 实现 → ✅ 原型完成 / ✅ 已接入 / ✅ 生产 / ⏸ 已推迟

> ⚠️ **✅ 已实现 ≠ 已接入生产**：状态列区分「原型完成未接入」（🟡 或 ✅原型）vs「已接入主系统」（✅ 已接入）。打 ✅ 前先问：接入主系统了吗？
```

## 7 类内容（主次分明，详略得当）

主文档按任务实际主次排——核心 flow 详写（图+状态表），次要内容概要 + 跳转。详细版下沉副文档。

### 1. 整个 flow 现状（核心，主）

```md
## 1. <flow 名称>

> 📄 详细 flow → [01-<主题>.md](01-<主题>.md)

<ASCII 图表示 flow：输入 → 处理 → 输出 → 注入/存储>

| 组件 | 状态 |
|------|------|
| <组件> | ✅/🔄/⏸ |
```

**多图原则**：记忆流 / hooks 触发 / 文件流 / API 接入 / 任务生命周期——每个主要 flow 一张 ASCII 图 + 状态表 + 跳转链接。

### 2. 工作历史（简）

```md
## N. 工作历史

| 日期 | 事件 | 结果 |
|------|------|------|
| <date> | <轮次/任务> | <结果> |

> 详细演进轮次 → <副文档>
```

### 3. 未来目标计划（简）

```md
## N. 未来目标计划

**目标**：<一句话目标>
**里程碑**：
- [ ] <M1>：<内容>
- [ ] <M2>：<内容>

> 详细计划 → <副文档>
```

### 4. 风险清单（简）


### 5. 已验证 vs 未验证（简）

```md
## N. 已验证 vs 未验证

> result_class 口径：不夸大完成度
```

### 6. 关键凭据/链接索引（简）

## 超大 docs 系统（二级副文档）

当副文档膨胀到需要细分时：

```
<工作区>/notes/design/<project>-design-sync/
├── PROJECT-SYNC-<date>.md          # 主文档
├── 00-待决策清单.md                 # 唯一 human 入口
├── 01-<主题>.md                     # 一级副文档（目录 + 跳转 + 概要）
├── 01-<主题>/                      # 二级副文档目录
│   ├── 01-<子主题1>.md
│   └── 02-<子主题2>.md
└── ...
```

- 一级副文档 = 该主题的目录 + 概要 + 跳转二级
- 二级副文档 = 详细设计
- 主文档只跳一级（不深层嵌套跳转）
