# 00-待决策清单格式模板（唯一 human 入口）

> 借鉴 grill-with-docs 的 grilling 方法论：设计树 frontier——每个决策分支展开，可立即回答的问题先列出。

## 头部

```md
# 分文档 00：待决策清单（唯一 human 入口）

> [⬆ 返回主文档](PROJECT-SYNC-<date>.md)

> **这是你唯一需要拍板的地方**。每项待决策含：**前因后果**（背景/轮次/证据）+ **待决策内容**（选项）+ **推荐选项**（理由）。
> 决策后：主文档状态表 + 相关副文档同步更新（按 doc-sync 同步规范）。
```

## 每项待决策模板

```md
### 决策 N：<决策标题> — <状态：待决策 / ✅ 已决策>

#### 前因后果

**为什么需要决定**：<背景，1-3 句>

**已经走过的轮次**（如果是多轮决策）：
| 轮次 | 结果 |
|------|------|
| <轮次 1> | <结果> |

**核心矛盾/证据**：<为什么现在需要拍板>（给绝对路径或链接）

#### 待决策内容

| 选项 | 说明 | 代价 |
|------|------|------|
| **A. <选项>** | <做什么> | <代价> |
| **B. <选项>** | <做什么> | <代价> |

#### 推荐选项

**推荐 <A/B>（<选项>）**，理由：
1. <理由 1>
2. <理由 2>
3. <理由 3>

> 若选 <另一选项>：<后果说明>
```

## 已决策历史表（ADR 风格）

```md
## 已决策（历史，供参考）

| 日期 | 决策 | 结果 |
|------|------|------|
| <date> | <决策内容> | <结果/落盘位置> |

> ADR 原则：记录*已决定*和*为什么*，单段可记录；难回退 / 无上下文会奇怪 / 真实权衡的决策才记录。
```
